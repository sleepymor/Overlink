## Lesson — Git `R0xx` similarity is not Unity GUID reuse
- Mneme's first review returned `FAILED` on two staged `.meta` files shown as `R079` renames from deleted `Assets/Cards/card_new*.asset.meta`, read as inherited GUIDs. Evidence disproved it: deleted GUIDs `05ce893829c765b438adf67ba85c25b5` and `05f9088946d0d2b4fa3029b7c6c2e2d6` are absent from the staged tree; new GUIDs are distinct (font `7ffd8c9875df2544fa613c90621b68c1`, post-process `7c91955d4f29cc1428283fc9499029b1`) and are the ones actually referenced by staged scenes/prefabs. Focused reassessment = `VERIFIED`; no metadata rewrite was needed. <!-- project: github.com/sleepymor/Overlink -->
- Rule: Unity `.meta` files share a near-identical serialized skeleton, so delete+add pairs routinely score as `R0xx` renames. Before mutating metadata on a rename finding, compare the **`guid:` values** and grep the staged tree for the old GUID. Rewriting valid GUIDs to defeat a heuristic would break every reference pointing at them.
- Corollary for reviewers: hand Mneme the GUID comparison, not just the `--name-status` summary, or the heuristic will read as a defect.

## Lesson — PowerShell wrapping of `gh` probes
- `@'RELEASE_NOTES'@` with text on the header line is a parse error; the whole command died **before** `gh` ran, so no release was created. Build multi-line notes with an array joined on "`n" and write to a temp file for `--notes-file`.
- `$ErrorActionPreference='Stop'` + `@(gh release view <tag> ... 2>&1)` turns gh's *expected* `release not found` stderr into a terminating error, aborting the script before `release create`. Either drop `Stop` around the absence probe, or skip the probe once absence is already established. Two publication attempts were wasted on this.
- Verified-safe pattern used for the successful publish: write notes → `gh release create … --prerelease` → check `$LASTEXITCODE` → `gh release view … --json tagName,isPrerelease,publishedAt,url`.
