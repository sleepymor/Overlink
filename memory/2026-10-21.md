## CI workflow defects found and fixed (all evidence-backed) <!-- project: github.com/sleepymor/Overlink -->
1. **`buildPath` is not a valid `game-ci/unity-builder@v4` input.** The correct name is `buildsPath`, and output always lands in `<buildsPath>/<targetPlatform>`. The invalid input was silently ignored — Actions only emitted `##[warning]Unexpected input(s) 'buildPath'` — so Unity wrote to `build/StandaloneWindows64` while the Zip step ran `cd build/Windows` → `No such file or directory`, exit 1. **The Unity build itself succeeded** (`Build Finished, Result: Success`); only packaging died. Fixed in `4c418a6`, which also added missing/empty-dir guards, zips the dir *contents* so `Overlink.exe` sits at archive root, and added a `Resolve release tag` step reused by both the upload and butler push.
2. **`broth.itch.ovh` is dead** — `curl: (6) Could not resolve host`, exit 6, killing `Install Butler`. Not a runner glitch: DNS fails from Tethys too while `itch.io` resolves normally. itch.io's butler "Installing" docs now publish **`broth.itch.zone`** as the CI route. Verified the new URL returns HTTP 200 and a genuine archive (`butler` 23.9 MB, `7z.so`, `libc7zip.so`) *before* committing. Fixed in `5102af3`.
3. **`butler push` has no `--target` flag.** I had already drafted that addition; checking the official *pushing* docs first showed platform tagging derives from the **channel name** (a channel containing `win`/`windows` is tagged Windows). Our channel is already `windows`, so nothing is required. Adding the flag would have failed the push on an unknown option.
4. **Duplicate release asset blocks re-runs.** The cancelled run had already uploaded `Overlink-Windows.zip` (32,567,375 bytes). `softprops/action-gh-release` errors `already_exists` on a same-named asset, so the next attempt would die at upload. Added `overwrite: true` in `199a958`.
- Debug technique that worked: `gh run view --log` / `--log-failed` are **refused while any job in the run is still in progress** ("logs will be available when it is complete"). Per-job logs are available immediately via `curl -sSL -H "Authorization: Bearer $(gh auth token)" https://api.github.com/repos/<owner>/<repo>/actions/jobs/<jobid>/logs`. Assign/trim `gh auth token` into a variable first — inline interpolation produced a 401 Bad credentials.
- All six repo secrets confirmed present (names only): `BUTLER_API_KEY`, `ITCH_USERNAME`, `ITCH_GAME_SLUG`, `UNITY_EMAIL`, `UNITY_LICENSE`, `UNITY_PASSWORD`.

## WebGL must play in-browser, not ship as a zip (Master correction) <!-- project: github.com/sleepymor/Overlink -->
Master corrected the goal: the WebGL build exists so players can **play directly on itch.io without downloading**. Shipping `Overlink-WebGL.zip` as a release asset was wrong.

- **My first hypothesis was wrong and I retracted it.** I suspected Gzip-without-decompression-fallback (`webGLCompressionFormat: 0` + `webGLDecompressionFallback: 0`). Inspecting the actual artifact disproved it: the build ships **`.br` (Brotli)** — `Overlink.wasm.br`, `Overlink.data.br`, `Overlink.framework.js.br`. itch.io's HTML5 docs confirm it sets `Content-Encoding: br` for any `.br` extension. Compression settings were left **untouched**; "fixing" them would have been a change to something already correct.
- **Real root cause:** `unity-builder` nests WebGL output one level down — `build/WebGL/Overlink/index.html`. itch.io requires `index.html` at the **root of the pushed channel**; nested means no entry point is detected, so the upload lands as a download instead of a playable game. Windows was already correct (`Overlink.exe` at zip root, no wrapper folder).
- **Fix — commit `7140a00`** (pushed, remote head verified): added a `Resolve content root` step that finds `index.html` at depth ≤2 and **fails the WebGL job loudly** if absent (so a broken channel is never pushed); pushes the resolved root instead of `matrix.buildPath`; gated `Zip build` + `Upload build to release` to `matrix.targetPlatform != 'WebGL'`; removed `zipName` from the WebGL matrix entry. A local validator confirmed both `zipName` references sit behind the `!= 'WebGL'` guard, so the WebGL job cannot hit an undefined matrix key.
- **Verified by run `39538577177` — both jobs `completed / success`.** From the WebGL job log (job `119020842813`), not inferred: `Content root: build/WebGL/Overlink`, `-rw-r--r-- 1 root root 5394 index.html`, `./butler push "build/WebGL/Overlink"`, `Pushing 11.39 MiB (18 files, 3 dirs, 0 symlinks)`, `Build is now processing`.
